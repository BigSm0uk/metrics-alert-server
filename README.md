# Metrics Alert Server

Система сбора метрик и алертинга, состоящая из сервера (сбора и хранения) и агента (сбора и отправки).

## 🏗 Структура проекта

- `cmd/server` — Точка входа для сервера.
- `cmd/agent`  — Точка входа для агента.
- `internal/`  — Основная бизнес-логика, репозитории и обработчики.
- `pkg/`       — Пакеты общего назначения и сгенерированный код (OpenAPI).
- `api/`       — Спецификации OpenAPI и документация.
- `profiles/`  — Результаты профилирования (pprof) и их анализ.
- `taskfiles/` — Модульные задачи для Taskfile.
- `.tools/`    — Вспомогательные инструменты для тестирования (автотесты Практикума).

## 🚀 Быстрый старт

Проект использует [Taskfile](https://taskfile.dev/) для автоматизации рутинных задач. Введите `task --list` для просмотра всех доступных команд.

### Сборка и запуск

```bash
# Сборка всех бинарников (server, agent)
task build:all

# Запуск сервера с PostgreSQL (требуется конфиг в config/config.local.yaml)
task server:run

# Запуск сервера с in-memory хранилищем
task server:run:mem

# Запуск агента
task agent:run
```

## 🛠 Автоматизация (Taskfile)

В проекте настроено множество задач для удобной разработки:

- **Форматирование**: `task format` автоматически исправляет стиль кода через `gofumpt` и `gci`.
- **Генерация кода**:
  - `task oapi:gen` — генерирует Go-код из OpenAPI спецификации.
  - `task reset:gen` — генерирует методы `Reset()` для структур с комментарием `// generate:reset`.
- **Тестирование**:
  - Модульные тесты через `task test`.
  - Автотесты Яндекс.Практикума (инкременты 1-14) доступны через `task iter<N>` (например, `task iter10`).

## 📚 Документация

В проекте есть несколько видов документации:

1. **OpenAPI (Swagger)**:
   - Спецификация находится в `api/metric/openapi.yaml`.
   - Для сборки и просмотра HTML-документации выполните `task redoc:bundle`. Результат будет в `api/docs/redoc.html`.
2. **Godoc**: 
   - Запустите локальный сервер документации командой `task godoc:run`. Она будет доступна на [http://localhost:6065](http://localhost:6065).

## 📊 Профилирование и Profiles

Директория `profiles/` содержит результаты анализа производительности и рекомендации по оптимизации.

### Работа с профилями
Задачи pprof выведены в отдельное пространство имен:
- `task pprof:save:base` — сохранить "базовый" профиль памяти до оптимизаций.
- `task pprof:save:result` — сохранить профиль "после" изменений.
- `task pprof:compare` — сравнить два профиля и увидеть разницу в аллокациях прямо в консоли.
- `task pprof:web` — открыть интерактивный веб-интерфейс для анализа.

## 🔧 Инструменты (Tools)

- `.tools/` — содержит бинарник `metricstest` для проверки соответствия инкрементам. Настройки тестов (база данных, порты) вынесены в `.tools/Taskfile.yml`.
- `cmd/reset` — кастомный генератор кода для упрощения работы со структурами данных.
